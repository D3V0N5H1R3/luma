# Learnings — Standard Library

> **See also:** Type checking of stdlib calls uses the catalog — see [learnings-compiler.instructions.md](learnings-compiler.instructions.md) for how the compiler resolves stdlib calls.

## Module Layout & Key Files

- Stdlib has 52+ files: 37 module namespaces plus infrastructure (`native_function.hpp`, `function_builder.hpp`, `container_ops.hpp`, `container_module_builder.hpp`, `path_validator.hpp`, `error_messages.hpp`, `stdlib_registry.hpp`, `platform_socket.hpp`, `platform_time.hpp`, `terminal_input.hpp` + platform-specific `terminal_input_posix.cpp`/`terminal_input_win32.cpp`) and shared helpers (`numeric_converters.hpp`, `numeric_helpers.hpp`, `value_compare.hpp`, `xml_module_internal.hpp`, `file_helpers.hpp`, `escape_helpers.hpp`, `hash_module_internal.hpp`, `http_module_request.hpp`, `http_module_connection.hpp`).
- Stdlib module registration uses a fluent DSL: `ModuleBuilder{"Array", env}.func("length", 1).extract_body(expect_array, impl)`. `FuncBuilder<Self>` separates type extraction (ExtractFn) from implementation (BodyFn) for clearer error contexts.

## Stdlib Infrastructure

- **ErrorMessages** (`error_messages.hpp`): Centralised error message factories and machine-readable error code constants in `error_codes` namespace (`empty_container`, `index_out_of_bounds`, `key_not_found`, `type_mismatch`, `division_by_zero`, `size_limit_exceeded`, `parse_error`, `io_error`, `invalid_argument`, `not_found`). All stdlib modules use these for consistent error reporting. Two styles: **unqualified** (short, e.g. `"index 5 out of bounds for array of length 3"`) and **qualified** (prefixed, e.g. `"Array.get: index 5 out of bounds (size 3)"`). Prefer qualified variants in new code. Qualified helpers include: `expected_type`, `empty_container`, `index_out_of_bounds`, `key_not_found`, `invalid_argument`, `division_by_zero`, `value_out_of_range`, `size_limit_exceeded`, `result_exceeds_maximum_size`, `must_be_non_negative`, `must_be_positive`, `conversion_error`, `parse_error`, `io_error`, `not_found`.
- **ContainerOps<Container, ReverseEach>** (`container_ops.hpp`): Template registering standard operations (`length`, `is_empty`, `to_array`, `map`, `filter`, `reduce`, `each`, `partition`, `concat`) for any container with a `std::vector<Value>` elements member. Used by Queue, Stack, and Set to eliminate near-identical implementations. The `ReverseEach` template parameter (default `false`) uses `if constexpr` to dispatch iteration direction for `each()`.
- **Stdlib registration is eager only.** `register_all(env, sandbox)` binds every active module at startup, and every entry point (CLI run, `--test`, REPL, `--eval`, debugger) uses it. The lazy path (`register_all_lazy`, `LazyRegistry`, `LazyLoader`, `Environment::set_lazy_loader`) was removed because nothing called it. While it existed, it was a second registration path that had to mirror every sandbox and postamble rule, and the VM's `GetGlobal` bypassed `Environment::get` and so never triggered it. Don't reintroduce on-demand module loading without a real caller and a measured startup win.
- **NativeFunctionValue is `{name, function}` only.** Parameter and return types live in the `StdlibCatalog`, never on the runtime value; the unused `parameter_types`/`return_type` fields were removed.
- **StdlibCatalog** (`shared/stdlib/stdlib_catalog.hpp`): Single source of truth for function metadata (arity, params, return types, param types, capabilities). Both type checker and language server derive from it. `Capability` tags (`None`, `FileSystem`, `Network`, `Process`, `Console`) are metadata, not the sandbox gate: they only derive `sandbox_blocked_modules()` (used to word the sandbox error); `Capability::None` does not mean "available under `--box`" (in-memory `Csv`/`Xml` members and the withheld members of sandbox-aware modules are `None`). `ReturnTypeDesc` describes return types without depending on TypeInfo — lightweight descriptors convertible to TypeInfo by the type checker. The stdlib namespace list is derived from the catalog — not hardcoded. `FunctionSpec` includes `param_types` vector for structured parameter type info, auto-derived by `StdlibTypeHandler::init_param_types()`.
- **Stdlib record identity is the bare short name — unless two stdlib records share it.** The type checker treats a record type as its declaration name (`add_record` in `stdlib_type_arities.cpp` uses the text after the last dot) and the runtime compares `RecordValue::type_name`, so `Math.Interval` (`minimum`/`maximum`) and `DateTime.Interval` (`start`/`end`) used to be one type `"Interval"`: assigning one to the other type-checked and failed at runtime. Records whose short names collide must use the qualified name everywhere — `add_record_with_identity(..., RecordIdentity::FullName, ...)`, a qualified `named::*()` descriptor in `stdlib_catalog_internal.hpp`, and the same qualified `type_name` in the module. `TypeMatcher::matches_simple_type` lets a qualified pattern (`is<Math.Rectangle>`, `case Math.Rectangle {…}`) match a record whose runtime `type_name` is the bare member; before that, such type tests on stdlib records were always `false` and record patterns silently never matched.
- **StdlibRegistry** (`stdlib_registry.hpp`): Module table mapping module names to registration functions with `os_only` and `sandbox_aware` flags (unified — no special-case sandbox handling outside the table). O(1) lookup via static hash map built on first call. 25 always-available + 8 OS-only + 4 sandbox-aware (Compression, Hash, Log, Terminal) = 37 module namespaces.
- **Stdlib choice variants: unit variants are `ChoiceValue` globals, payload variants are `NativeFunctionValue` constructors** (`register_stdlib_postamble`, `stdlib_registry.hpp`). The postamble walks every choice in `stdlib_choice_types()` and binds `Namespace.Type.Variant` at runtime. A **unit** variant (no fields, e.g. `Log.Output.Stdout`, `Terminal.Key.Enter`) binds a field-less `ChoiceValue` — it is a `GetGlobal` lookup, so it MUST stay a value. A **payload** variant (`variant.fields` non-empty, e.g. `Log.Output.File(path)`, `Json.Value.JsonString(s)`, `Xml.Node.Element(...)`, `Terminal.Key.Character/Function`) binds a `NativeFunctionValue` whose body builds `ChoiceValue{type_name=ch->name, variant, fields=[copied args]}`, mirroring `handle_make_choice_constructor` (`vm_dispatch_construction.cpp`). Originally the postamble registered *every* variant as a field-less `ChoiceValue`, so calling a payload variant threw "cannot call 'X'" at runtime even though the type checker accepted it — **no stdlib payload-variant was runtime-constructible**. `match` is unaffected by the representation: the compiler emits `Op::IsType` with the variant name from its compile-time name table and `TypeMatcher` inspects `ChoiceValue.variant`/`type_name` directly — it never reads the runtime global binding. Consequence for the conformance test (`stdlib_catalog_conformance_test.cpp`): payload constructors are now `is_native_function()`, not `is_choice()`, so `test_all_registered_functions_are_in_catalog` must skip any binding whose name is a known choice-variant full name (built from `stdlib_choice_types()`), not just skip `value.is_choice()`.
- **ReDoS Validation Cache** (`regularexpression_module.cpp`): Thread-safe cache (`std::unordered_set<std::string>`, max 1024 entries, mutex-guarded) of regex patterns that have passed ReDoS safety validation. **Both the heuristic and the cache key use the *cleaned* pattern** — the text after `parse_named_capture_groups` strips named-group syntax, i.e. exactly what is handed to `std::regex` — and the key is prefixed with the case-insensitive flag (`"i:"`/`"s:"` + cleaned). Checking the raw pattern let named groups, `\x` escapes, and case-insensitive mode bypass the guard (`(a|A)+` is ambiguous only under icase). `has_dangerous_quantifier_nesting(pattern, case_insensitive)` uses a single bounds-checked pass with a per-group state stack to detect two catastrophic-backtracking shapes under repetition: (1) **nested quantifiers** like `(a+)+`, and (2) **ambiguous alternation** whose branches overlap on their first token like `(a|aa)+`, `(.|a)+`, or `(a|)+` (an empty branch). Under icase it folds ASCII case before comparing first tokens; `\x`, `\u`, `\c`, and back-references count as wildcards, and `\n`/`\t`/… map to the real control character. Disjoint alternation such as `(cat|dog)+` or `(a|b|c)+` stays accepted. It deliberately prefers false positives (rejecting a borderline-safe pattern) over false negatives, since `std::regex` backtracking is catastrophic on some standard-library implementations even where MSVC happens to optimise it. `is_pattern_redos_safe(pattern, case_insensitive)` checks cache first (lock-guard), validates if missing, caches on success. The `*_with` functions read their flags *before* the guard so it can fold case. Prevents re-parsing identical patterns in loops.
- **Compiled-Regex Cache** (`regularexpression_module.cpp`): Sibling to the ReDoS validation cache but distinct — a thread-safe `LruCache<std::string, std::shared_ptr<const std::regex>>` (max 256 entries, mutex-guarded) that memoizes *compiled* `std::regex` objects so hot loops don't recompile the same pattern each call. `get_compiled_regex()` compiles **outside** the lock (only `get()`/`put()` are guarded) so callers never serialize on the regex engine, and returns a `shared_ptr<const std::regex>` so the handle stays valid and immutable after the lock is released — concurrent const `regex_search`/`regex_replace` on it are data-race free. Unlike the validation cache (which never evicts and simply stops inserting once full), this cache evicts its least-recently-used entry on overflow via `LruCache`, so a hot new pattern encountered after the cache fills still gets cached instead of being permanently shut out. Keyed by `make_regex_cache_key(cleaned_pattern, flags)` — the numeric `syntax_option_type` flags, a `:`, then the pattern — so the same pattern compiled with `icase`/`multiline` by the `*_with` functions never aliases the flagless automaton. Only ReDoS-safe, size-checked patterns ever reach it (validation runs first), so no dangerous pattern is compiled or cached; invalid patterns throw `std::regex_error` from construction exactly as before.
- **Bound output size while producing it, not after.** Regex `replace*` go through `bounded_regex_replace` (match iterator plus a size-checked writer, so `$&` expansion is bounded too); `String.indent`, `insert`, `replace_range`, and `replace` compute or check the result size before allocating; `Array.windows` checks `window_count > max_array_size / size`; `LinearAlgebra.outer` calls `require_matrix_within_limit` first; `split_whitespace` checks the array limit per token. `Json.to_string` (`LumaToJsonConverter`) enforces `json_depth_limit()`, `max_json_elements`, and a `max_string_size` byte budget — its unbounded recursion could overflow the native stack from a value built at runtime, which nothing (not even `--box`) could catch.
- **`String.template` is single-pass**: substituting into its own output let a value containing `{other_key}` expand a second time (template injection). Values are inserted literally; unknown placeholders are kept as written.
- **Check every argument after the first with `expect_*`.** Reading `args[1]` with an unchecked `as_*()` turned a wrong argument type into an opaque "internal error". `define_method`'s extracted `self` is bound with `decltype(auto)`, so string/container extractors yield a reference into `args[0]` instead of a copy per call.
- **`gzip_decompress_checked` must validate the FEXTRA field length before trusting it** (`compression_codec.cpp`): the gzip header's optional FEXTRA subfield stores a 2-byte little-endian `xlen` that the decoder adds to `offset` to skip past it. An untrusted/corrupt stream can claim an `xlen` far larger than the remaining input, so the code checks `offset + 2 + xlen > input.size()` and returns `DecodeError::Truncated` *before* advancing `offset` — skipping this check let `offset` run past `input.size()`, corrupting all subsequent header parsing on crafted/truncated `.gz` input. Any length-prefixed field read from untrusted binary input needs its length validated against the remaining buffer before use, not just at final bounds-checked reads.

## Common Utilities

- **Never wait on tasks or channels with a short `sleep_for` poll** (`BackoffTimer`): on Windows even `sleep_for(1ms)` lasts a full scheduler tick (~15.6 ms), so `Task.race`/`Task.any` used to cost ~15.6 ms per call while `Task.all` (blocking on `future.get()`) cost ~1 ms. Waiting on tasks goes through `TaskCompletion` (`runtime/concurrency/task_completion.hpp`): the spawn worker marks it complete after satisfying the promise, and a waiter holds a scoped `CompletionSubscription` that blocks until any subscribed task finishes. The subscription must be scoped (unsubscribing on destruction) — a long-running task raced in a loop would otherwise accumulate one stale signal per call. `Channel.select` still polls with `BackoffTimer` because channels have no wake-up notification yet.
- **Result<T, E>** (`core/common/result.hpp`): Generic result type modeled after Rust's `Result<T, E>`. Static factories `Result::ok(value)` and `Result::err(error)`. Default error type is `std::string`. Use over `std::optional<T>` when failure reasons vary and must be communicated.
- **StringHash / StringMap\<V\> / StringSet** (`core/common/string_hash.hpp`): Transparent hash functor enabling heterogeneous lookup — `std::string_view` can be passed to `find()`, `contains()`, `count()` without allocating a `std::string`. Use `StringMap<V>` and `StringSet` aliases for string-keyed containers throughout the codebase.
- **format_number()** (`core/common/format_number.hpp`): Formats doubles with trailing zero trimming while keeping at least one digit after the decimal (e.g., `3.0`, `1.5`, `-0.25`). Consequence: a whole `number` (double) always prints with a trailing `.0` (e.g. `42` → `"42.0"`); flooring/rounding the value is *not* enough to display an integer-looking string — convert to the `integer` type (`Converter.to_integer`) so it formats without the decimal.
- **has_directory_traversal()** (`core/common/path_utils.hpp`): Returns true if any path component is `..` or `.` (so `./x.luma` is rejected too). Used for include path security validation.
- **path_from_utf8() / path_to_utf8()** (`core/common/path_utils.hpp`): The only correct way to turn Luma (UTF-8) text into a `std::filesystem::path` and back. On MSVC, `path{std::string}` and `path::string()` use the ANSI code page, so a non-ASCII include path or `PATH` entry was decoded wrongly or threw. `try_path_from_utf8` is the non-throwing form for user-supplied text.
- **platform_utils** (`core/common/platform_utils.hpp`): Header-only shared utilities for platform-abstracted environment access. `wstring_to_utf8()` (Win32-only, `WideCharToMultiByte`) and `safe_getenv()` (Windows: `_wdupenv_s` converted to UTF-8 with RAII; POSIX: `std::getenv`). Used wherever environment variables or wide-string conversion is needed. Callers that build paths from `safe_getenv()` output must use `path_from_utf8`.
- **utf8_decode()** (`core/common/utf8.hpp`): Strict RFC 3629 decoder returning `{codepoint, length}`; overlongs, surrogates, `C0`/`C1`/`F5`–`FF` lead bytes, and truncated sequences decode as `{U+FFFD, 1}`. **Advance by the returned `length`, never by the lead byte's nominal length** — the old decoder accepted overlongs and its iterator could step past `size()`, which surfaced as `out_of_range` in `String.insert`/`delete`/`replace_range`.
- **file_time_to_system_clock()** (`core/common/file_time.hpp`): Header-only, feature-tested conversion of a `std::filesystem::file_time_type` to a `std::chrono::system_clock::time_point`. Uses `std::chrono::clock_cast` when available (`__cpp_lib_chrono >= 201907L`), else rebases the file-clock time point onto the system clock — Apple libc++ (and some others) do not provide `clock_cast`. Single home for the FileSystem module's `clock_cast` call site that broke the macOS build.
- **LruCache<Key, Value, Hash>** (`core/common/lru_cache.hpp`): Header-only LRU cache. O(1) lookup, insertion, and eviction via `std::list` (LRU order) + `std::unordered_map` (key → list iterator). Front = MRU, back = LRU. `put()` returns a `Value&`; `get()` promotes to MRU and returns pointer or nullptr. Not thread-safe — callers must guard externally. Used by `ExpressionEvaluator` (expression cache), `LspAnalysisService` (document analysis cache), and the compiled-regex cache (`regularexpression_module.cpp`).
- **`compute_slice_range()` (`core/common/index_validator.hpp`) clamps `end` into `[0, size]` via `std::clamp`, not a one-sided `std::min(end, size)`**: after `RangeEnd::Inclusive` adds 1 to an already-normalized negative index, `end` can still be negative (e.g. an inclusive range whose end index is more negative than `-size`), and a bare `std::min(end, size)` would let that negative value flow into the returned `SliceRange` unclamped on the low side, producing a `start > end` or negative-width range a caller iterates unsafely. `std::clamp(end, 0, size)` closes that gap; `start` already had its own explicit `std::max(start, 0)`.
- **VariableReferenceRegistry\<T\>** (`debugger/source/variable_reference_registry.hpp`): Generational registry replacing per-frame `std::unordered_map<int, T>` in `VariableInspector`. `allocate()` assigns an ID and records the current generation. `lookup()` returns `std::nullopt` for stale (wrong-generation) entries. `advance_generation()` + lazy `purge_stale()` provides O(1) bulk invalidation — far cheaper than clearing maps every resume.
- **escape_string_impl\<EscapePolicy\>** (`core/common/escape.hpp`): Policy-based escape engine. An `EscapePolicy` provides either `escape_char(char, std::string&)` or `try_escape(char) → optional<string_view>`. Built-in policies: `JsonEscapePolicy`, `XmlEscapePolicy`, `JsEscapePolicy`, `HtmlEscapePolicy`. `json_escape()` and `js_string_escape()` are thin wrapper functions returning strings; `json_escape_string()`, `xml_escape_string()`, and `html_escape_string()` append directly to an output buffer (zero intermediate allocations). All input parameters accept `std::string_view`. Add new escape variants by defining a policy struct — no code duplication.
- **HandlerRegistry\<HandlerFn\>** (`shared/protocol/handler_registry.hpp`): Generic method→handler dispatch map template used by both LSP and DAP servers. `register_handler()` throws `std::logic_error` on duplicate (works in Release builds unlike assert). `find()` returns `const HandlerFn*` (nullptr if unknown). Populated once at startup, read-only thereafter — no locking needed.
- **CompilerLimits / OptimizerLimits** (`core/runtime/compiler/compiler_limits.hpp`): Consolidated `static constexpr` limit constants for the compiler and optimizer. Replaces 14+ scattered constants across compiler.hpp, optimizer.cpp, and bytecode_serializer.cpp. `compiler.hpp` aliases them for backward compatibility.
- **ParsedUrl** (`core/runtime/stdlib/io/http_url_parser.hpp`): Lightweight URL parser for HTTP(S) requests. Extracts scheme, host, port, path, and query. IPv6-aware (handles `[addr]:port` bracket syntax). Header-only for reuse across stdlib modules.
- **LspConfig / ConfigSnapshot** (`language-server/source/lsp_config.hpp`): Uses copy-on-write snapshots. `get()` briefly acquires `update_mutex_` to copy the `shared_ptr`, then callers access the immutable `ConfigSnapshot` fields lock-free. The comment "without holding any lock" was incorrect — `get()` *does* hold the mutex briefly. Writers call `apply_lsp_settings()` / `apply_project_config()` which build a new snapshot and publish atomically. Callers: `config().get()->analysis_debounce_ms` pattern.
- **HandlesAll concept** (`core/analysis/ast/ast_dispatch.hpp`): `template<typename H, typename... NodeTypes> concept HandlesAll = (requires(H&& h, const NodeTypes& node) { h(node); } && ...)`. Used to build `ExpressionHandler`, `StatementHandler`, `DeclarationHandler` concepts as one-liners. Catches missing handler overloads at the call site rather than inside the switch body.
- **OrderedLockGuard\<LockIdType\>** (`debugger/source/dap_session_types.hpp`): Class template constrained by `LockId` concept (`std::is_enum_v<T> && std::totally_ordered<T>`). In debug builds, applies DAP lock-ordering assertions via `if constexpr (std::same_as<LockIdType, DapLockId>)` — other conforming enums are accepted and lock/unlock without ordering checks. `OrderedUniqueLock` variant exposes `underlying()` for `condition_variable::wait()`.

## OS Boundary

- **Enforce size limits while reading, not before.** Every file read (`FileSystem.read_*`, `Hash.*_file`, `read_file_contents`, KeyValueStore) goes through `read_file_bounded()`; the on-disk size is only an allocation hint, since a file can grow between `file_size` and the read. Console line reads share one bounded reader that discards an over-long line so the next read starts fresh.
- **Never use `select()`/`FD_SET` on POSIX** — a descriptor ≥ `FD_SETSIZE` (1024) writes past a stack buffer. POSIX socket waits use `poll()`; Windows keeps `select()`, which has no such overflow.
- **Child processes inherit nothing by accident.** POSIX pipes and sockets are close-on-exec; on Windows the child gets an explicit handle allow-list (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`) containing only its own stdout/stderr pipe ends, and sockets are non-inheritable. Pipe ends and handles are owned by RAII wrappers (`UniqueFd`/`UniqueHandle`), and `Process.run` tokenizes the command before creating pipes, so a parse error cannot leak them. Remaining gap: POSIX `std::ofstream` files (e.g. the Log output file) are not close-on-exec.
- **Windows refuses `.bat`/`.cmd` as a direct command** (`is_windows_batch_script()` plus `windows_launch_refusal()`): `cmd.exe` re-parses their arguments, so quoting cannot be made safe ("BatBadBut"). A name-only check is not enough — Windows normalises the program path before launching, so `x.bat\.` or `x.bat/.` still ran the batch file through `cmd.exe`. The name check strips trailing separators, `.` components, dots, spaces, drive/directory and `::$DATA` repeatedly; names ending in `.`, a space, `/` or `\` are refused outright; and the program is resolved the way `CreateProcess` would (`GetFullPathNameW`/`SearchPathW`) and the resolved file's extension is checked too. Arguments containing NUL are refused (NUL would end the command line early). Naming `cmd.exe` explicitly still works.
- **Range-check pids before narrowing**: `Process.signal(4294967295, …)` truncated to `pid_t` −1 and became `kill(-1, SIGKILL)`. Pids above 32 bits are rejected in the module, values outside `pid_t` in the POSIX layer, and pid ≤ 0 on Windows.
- **Timeouts kill the whole tree and still apply after the child closes its output**: POSIX timeout children get their own process group; the wait keeps honouring the deadline after both pipes close.
- **Try every resolved address** (`tcp_connect_any()`), for Socket connects, listens, and Http. The SSRF check already covers all addresses.
- **HTTP response parsing is fail-closed**: `ChunkedBodyDecoder` parses chunk sizes with an overflow check, bounds them by the response limit, always moves forward, and resumes incrementally (the old parser could loop forever at 100% CPU and was O(n²)). A truncated, oversized, or malformed response is `Http.Error.Malformed`, not `success`; chunked wins over `Content-Length`. Timeouts are clamped to [1, `INT_MAX`] ms.
- **Replace state only after the new state is ready**: `Log.set_output` opens the new file before closing the old one; `KeyValueStore` saves through a unique temp file, flushes and checks it, renames atomically, removes the temp file on every failure, and has no non-atomic copy fallback.
- `FileSystem.delete_directory` refuses the working directory and its parents (compared by file identity), so `delete_directory(".")` can no longer wipe the tree it runs in.

## Sandbox Mode

- `--box` flag disables OS-accessing modules: Console, Csv, FileSystem, Http, KeyValueStore, Process, Socket, Xml.
- **Two independent tables encode the sandbox boundary and must agree**: the registry's `os_only` flags (`kModules` in `stdlib_registry.hpp`, which decide whether a module is *registered* at all when `sandbox=true`) and the catalog's capability-derived blocked set (`stdlib::sandbox_blocked_modules()`, which produces the "not available in sandbox mode" lookup error). If a new OS-capable module is added to one table but not the other, it could be silently reachable in the sandbox. `tests/runtime/stdlib_catalog_conformance_test.cpp` now cross-checks that the two sets are identical, and additionally exercises the real enforcement path (`Environment::get` in a sandbox env throws for each blocked module; safe modules resolve). Enforcement itself lives in `Environment::get` → private `verify_sandbox_access` → root-scope `SandboxPolicy` (`sandbox_policy.hpp`). The normative security model — assets, adversary, guarantees, and the crucial *language-level, not OS-level* caveat (a memory-safety bug escapes the sandbox, hence the coupling to fuzzing) — is documented in `documents/Luma_Sandbox.md`.
- The program-executing fuzzers (`fuzz_vm`, `fuzz_structured`, and everything via `fuzz_pipeline.hpp`) register the stdlib with `sandbox=true`, so generated programs cannot perform real host side effects during fuzzing and the sandbox surface is continuously exercised; `fuzz_path` carries a path-escape oracle.
- Individual file-I/O functions (like `Compression.gunzip_file`, `Hash.sha256_file`, `Log.set_output`) also use `if (!sandbox)` guards. **Terminal is sandbox-aware too**: under `--box` it withholds its console-input functions (`enable_raw_mode`, `enable_mouse`, `read_key`, `read_key_timeout`, `get_input`, `read_line`, `get_cursor_position`) — it used to read the console in the sandbox, contradicting `Luma_Sandbox.md`. Withheld functions stay `Capability::None` in the catalog (like `Log.set_output`): tagging them `Console` would put the whole `Terminal` module in the blocked set and make typos of its still-available output functions report "not available in sandbox mode". They are blocked by name through `sandbox_withheld_functions()` instead.
- HTTPS requires Mbed TLS (`LUMA_FEATURE_TLS`, default ON); when disabled, `https://` fails at runtime.
- **Every JSON entry point must clamp to the same `LUMA_LIMIT_MAX_JSON_NESTING_DEPTH`, not just the ones a reviewer thinks of first**: `json_module_parser.cpp`'s `Json.deserialize` passed the sandbox-configured limit to `json::JsonValue::parse`, but `json_value_module.cpp`'s `Json.parse`/`Json.parse_detailed` called `json::parse` with no depth argument at all — silently falling back to the parser's compile-time-only cap and letting `--box`'s tightened 32-deep limit be bypassed via those two functions. Fixed with a shared `json_depth_limit()` helper (`json_value_module.cpp`) that clamps `ResourceLimits::max_json_nesting_depth` to `CompileTimeLimits::max_json_depth` and is passed to every `json::parse` call site in that file. When a resource limit is sandbox-configurable, grep for *every* call to the underlying parser/deserializer, not just the module that was last touched — a second entry point into the same parser is an easy place for a limit to quietly not apply.

# Learnings — Compiler

## Module Layout & Key Files

- The compiler is split into core files: `compiler.cpp` (core), `expression_compiler.cpp`, `statement_compiler.cpp`, `optimizer.cpp` with sub-files `_constant_fold`, `_control_flow`, `_dead_code`, `_peephole`, and `optimizer_internal.hpp`. Further decomposed into: **PatternCompiler** (all pattern-matching compilation with `PatternTestArgs`/`GuardResult` structs), **VariableResolver** (3-level local→upvalue→global resolution with `VarSlot` struct), **ConstFolder** (compile-time constant folding for binary/unary ops via `IConstantEmitter` narrow interface). All helpers access the compiler through the **ICompilationBackend** pure virtual interface (implemented by **CompilerAccess**). Type definitions are extracted into `compilation_context.hpp` (CompilerScope, CompilationContext, Local) and `compiled_function.hpp` (CompiledFunction, FunctionDebugInfo). Supporting modules: `chunk.hpp/.cpp` (bytecode container), **ConstantPool** (extracted deduplication with `std::bit_cast` for doubles), `opcode.hpp` (105 opcodes), `emitter.hpp` (bytecode emitter helpers), `bytecode_serializer.hpp/.cpp` (persistent `.lumc` binary format), `compilation_cache.hpp/.cpp` (in-memory LRU cache), `verifier.hpp/.cpp` (structural bytecode verification).

## Non-Obvious Patterns

- The optimizer has 3 levels: L0 (none), L1 (peephole), L2 (adds `constant_fold`, `unary_fold`, `comparison_fold`, `dead_code`, `jump_threading`, `dead_store`, `tail_call` — run to convergence, then `compact()`). Cross-function inlining (`inline_small_functions`) must run before per-chunk `optimize()` so inlined code benefits from passes. Constant folding is handled by the extracted **ConstFolder** class.
- **Two optimizer passes were intentionally removed as unsound at the bytecode level** (documented at `optimizer.hpp:94-102`): the multiply→shift **strength reduction**, and **constant propagation** (`GetLocal`→`Constant` for single-assigned locals). The optimizer sees only a `Chunk` — no local scopes/liveness — so a slot holding a single-assigned constant can be freed at scope-exit and reused by a later binding whose initializer is left on the stack (an *invisible* write with no `SetLocal` opcode); the stale constant then propagates into the wrong variable's reads, miscompiling exotic shapes like `match case == <block-with-locals>`. Re-enabling either needs a proper per-slot liveness/depth analysis. Removing an optimization can only improve correctness, so removal (not a risky fix) is the project precedent — **do not naively re-add a propagation/strength-reduction pass.**
- **Chunk** (`core/runtime/compiler/chunk.hpp`): Bytecode container. Source map stored as sparse `(byte_offset, SourceLocation)` pairs — one entry per opcode saves ~60% memory vs per-byte tracking. Source-location bookkeeping and the deduplicating name pool are now extracted into focused **SourceMap** (`source_map.hpp`, a binary-searched sparse map) and **NameTable** (`name_table.hpp`, interned 16-bit name handles) types that Chunk composes — so the name vector and its O(1) dedup index can no longer drift out of sync. **ConstantPool** (`constant_pool.hpp`) extracted: manages constant deduplication (integers, strings, and doubles use separate maps; doubles use `bit_cast` for exact equality to distinguish `0.0` from `-0.0`). Max 65,536 constant pool entries (uint16_t addressing).
- **NameResolver** (`core/analysis/resolver/resolver.hpp`): Single-pass resolution assigning slot indices for O(1) VM access. `ResolvedVar` has `frame_depth` (0=local, 1=enclosing — relative, not absolute), `slot_index`, `is_mutable`. Marks `is_captured` when variable is used in nested scope for upvalue handling.
- **Value-block scratch slots (compiler invariant)**: local slots are assigned as `locals.size() - 1` (`declare_local`), which assumes the value being bound is the first temporary above the locals region. When a value-producing block — a `match`/`if` used as an expression, or any sub-expression that declares locals mid-compilation — is compiled while operand-stack temporaries are already live *beneath* it (e.g. the container+index of `container[index] = match {…}`, prior call arguments, the left operand of a binary op, dict keys, pipe stages, interpolation parts), the block's locals get slots that ignore those temporaries → `GetLocal`/`SetLocal` hit wrong stack positions → corruption (`cannot index-assign into 'string'`, `cannot call 'string'`, `bad variant access`, or silently wrong values). Fix: bracket every such site with `reserve_scratch_slots(count, loc)` / `release_scratch_slots(count)` (defined in `assignment_compiler.cpp`, declared on `compiler.hpp` and the `i_variable_manager.hpp` role interface) — they declare empty-named placeholder locals so block locals land at their true runtime slots; release emits **no** runtime pops (the temporaries are consumed by the trailing `IndexSet`/`SetField`/compound op). For a balanced single-scope pair prefer the `ScratchSlotGuard` RAII wrapper (`scratch_slot_guard.hpp`, mirrors `ScopeDepthGuard`) so the count is stated once and can't leak on an early exit; keep the explicit `reserve`/`release` calls only for per-iteration or unequal-count shapes. Existing callers: `assignment_compiler`, `binary_operator_compiler`, `collection_compiler`, `interpolation_handler`, `pipe_compiler`, `expression_compiler`, `declaration_compiler` (one slot around a default parameter value — `JumpIfFalse` *peeks*, not pops, its boolean condition, so that temporary stays live while the default, possibly a value block, is compiled), and `pattern_compiler` (value-form `match` reserves `subject_temps_below + 1` slots around each arm's pattern test — a `case == <expr>` comparison value can be an arbitrary locals-declaring block sitting above the untracked subject + `Dup` temps; value-form has 2 untracked temps below so `subject_temps_below=1`, statement-form's subject is a tracked hidden local so `subject_temps_below=0`). **When adding any compile path that leaves temporaries on the stack before compiling a sub-expression, you must reserve scratch slots** or you reintroduce this stack-corruption class.

## Bytecode Serialization & Caching

- Two-level caching system: (1) `CompilationCache` — in-memory LRU (default 128 entries), keyed by `(absolute path, content hash, options)`, thread-safe (mutex). (2) `BytecodeSerializer` — disk-based; `run_file` (in `cli_runner.cpp`) writes compiled bytecode to a `<source>.lumc` file **next to the source** via `BytecodeSerializer::cache_path_for`, which just does `replace_extension(".lumc")`. On the next run it reads/validates that file and skips compilation on a hit. The disk cache key mixes the source hash with the optimization level. Only normal runs write `.lumc`; `--check` and `--test` compile in memory only. `CompilationCache` is injectable via `run_file()` for testability.
- `.lumc` binary format: 24-byte header (`"LUMC"` magic, u32 format version, u32 flags, u64 source hash via **FNV-1a** — `fnv1a_hash`, not xxHash — u64 timestamp), followed by function table (count + per-function metadata, bytecode chunks, constant pools, source maps).
- `BytecodeSerializer` handles serialize/deserialize with typed `DeserializeResult` containing error codes (`BadMagic`, `VersionMismatch`, `CorruptFunction`, `HashMismatch`, etc.) and detail strings.
- Format version currently 2 (v1→v2 widened every serialized string's length prefix from u16 to u32, so a string constant or name of ≥ 65,536 bytes no longer wraps its prefix and desyncs the rest of the stream — `k_string_length_prefix_bytes` went 2→4 accordingly). Bump `k_bytecode_format_version` for incompatible changes.
- `BytecodeVerifier` validates structural integrity (valid opcodes, jump targets on instruction boundaries, constant/name indices in-bounds, stack depth simulation, upvalue/local slot ranges). Optional, disabled by default.
- **Bounds-check counts before `reserve()` when deserializing `.lumc`**: an attacker-controlled length (e.g. the source-map entry count) can otherwise trigger a huge `reserve()` and OOM. The deserializer rejects any count whose implied byte size exceeds the remaining input before reserving — `if (r.error() || !r.has_remaining(map_count * SerializerLimits::k_source_map_entry_bytes)) error;`. Apply the same `has_remaining()` guard to every `reserve(count)` driven by untrusted input — the top-level function vector likewise rejects `func_count` against `SerializerLimits::k_min_function_bytes` (31, the smallest a fully-empty serialized function can be) and returns `DeserializeError::BadFunctionCount` before `functions.reserve()`, joining the source-map (`k_source_map_entry_bytes`) and name-table guards (found via fuzzing the bytecode deserializer).
